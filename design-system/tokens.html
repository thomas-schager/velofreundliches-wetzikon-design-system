Design Tokens

Diese Seite ist eine reine, portable Referenz der Design-Tokens — Farben, Typografie-Skala, Abstände, Radien, Schatten, Layout- und Motion-Werte. Jeder Wert unten wird live über var(--…) aus ../tokens.css gelesen, nicht hier fest verdrahtet — was auf dieser Seite erscheint, ist also immer exakt das, was tokens.css aktuell enthält. Diese Datei ist die kanonische Quelle für beide Konsumenten: die öffentliche Contao-Site (VeloWetzikon_Contao) und die künftige Backend-/Admin-Anwendung. Komponenten (Buttons, Karten, Navigation, …), die auf diesen Tokens aufbauen, sind bewusst nicht hier dokumentiert — dafür siehe Contao-Implementierung.

Prinzip Überschriften, Content-Elemente
Vertikaler Rhythmus

Jede Überschrift steht näher bei dem Text, den sie einleitet, als beim Element davor — das Gestaltgesetz der Nähe: was inhaltlich zusammengehört, bekommt weniger Abstand; was zwei getrennte Gedanken sind, mehr. Gilt für jede Überschriftenebene und für die Abfolge ganzer Content-Elemente, nicht nur für h1/h2.

Erstes Element im Fluss0 — kein Element davor, also kein Abstand davor

Abstand davor > Abstand danach, bei jeder Ebene. Alle Werte aus der bestehenden --space-*-Skala, keine neuen Tokens nötig. Ausnahme: das erste Element im Fluss braucht keinen Abstand davor — es sitzt bereits im eigenen Top-Padding des Containers (siehe Erstes Element der Seite weiter unten), ein zusätzlicher Abstand davor wäre nur ein unmotivierter Leerraum ohne etwas, wovon er trennt. 

/* Überschriften: Abstand davor > Abstand danach, skaliert mit der Ebene.
   :where() setzt die Spezifität dieser Regel auf null, sodass JEDE andere Regel
   mit mindestens einer Klasse (.vw-heading h2, .vw-hero__title, .modal-title, …)
   automatisch gewinnt -- unabhängig von der Reihenfolge im Stylesheet. */
:where(.mod_article, .vw-prose-flow) h1,
:where(.mod_article, .vw-prose-flow) h2 { margin-top: var(--space-8); margin-bottom: var(--space-4); }
:where(.mod_article, .vw-prose-flow) h3,
:where(.mod_article, .vw-prose-flow) h4 { margin-top: var(--space-6); margin-bottom: var(--space-3); }
:where(.mod_article, .vw-prose-flow) h5,
:where(.mod_article, .vw-prose-flow) h6 { margin-top: var(--space-5); margin-bottom: var(--space-2); }

/* "Erstes Element im Fluss: kein Abstand davor" -- dafür reicht :first-child
   NICHT allein: es prüft nur die Position unter Geschwisterelementen im
   DIREKTEN Elternelement, nicht die Position im Dokument. In Contao bekommt
   jedes Content-Element seinen eigenen Wrapper-
 -- eine Überschrift ist
   also "erstes Kind ihres eigenen Wrappers" unabhängig davon, ob VOR diesem
   Wrapper schon etwas auf der Seite steht. Darum zusätzlich verlangen, dass
   auch der WRAPPER selbst erstes Kind von .mod_article ist -- nur dann ist die
   Überschrift wirklich die erste Sache auf der ganzen Seite. .vw-prose-flow hat
   keinen solchen Wrapper pro Element (ein durchgehender Fliesstext, keine
   Abfolge einzelner Contao-Elemente), darum reicht dort die einfache Prüfung. */
:where(.mod_article > [class*="content-"]:first-child) h1:first-child,
:where(.mod_article > [class*="content-"]:first-child) h2:first-child,
:where(.mod_article > [class*="content-"]:first-child) h3:first-child,
:where(.mod_article > [class*="content-"]:first-child) h4:first-child,
:where(.mod_article > [class*="content-"]:first-child) h5:first-child,
:where(.mod_article > [class*="content-"]:first-child) h6:first-child,
:where(.vw-prose-flow) h1:first-child,
:where(.vw-prose-flow) h2:first-child,
:where(.vw-prose-flow) h3:first-child,
:where(.vw-prose-flow) h4:first-child,
:where(.vw-prose-flow) h5:first-child,
:where(.vw-prose-flow) h6:first-child { margin-top: 0; }

/* Content-Element zu Content-Element (z.B. zwei Bilder hintereinander, oder ein
   natives Text-Element nach einem velo_*-Element): ein "lobotomized owl"-
   Selektor, bewusst nur margin-top, damit sich Abstände nie verdoppeln.
   content-velo-* nur auf der EMPFANGENDEN Seite (nach dem +) ausgeschlossen --
   das sind eigenständige Sektionen (Hero, Melde, Positions, Join, Newsletter,
   Tabs, Park-Test), die ihren Abstand bereits selber lösen, diese Regel darf
   dort nie zusätzlich draufaddieren. Auf der VORANGEHENDEN Seite gilt der
   Ausschluss bewusst NICHT: ein natives Element braucht seinen eigenen Abstand
   unabhängig davon, was davor steht, genau wie jedes velo_*-Element seinen
   schon unabhängig vom Vorgänger mitbringt.
   :is(...) statt nur [class*="content-"]: ein Content-Element vom Contao-Typ
   "Modul" (ein eingebundenes Frontend-Modul, z.B. eine News-Liste) bekommt GAR
   KEINEN content--Wrapper -- Contao gibt direkt die Modul-Klasse aus (z.B.
   
), darum greift [class*="content-"] dort nie.
   mod_*-Elemente sind nie gleichzeitig content-velo-*, der Ausschluss auf der
   Empfänger-Seite muss das also nicht extra abdecken. */
.mod_article > :is([class*="content-"], [class^="mod_"])
  + :is([class*="content-"], [class^="mod_"]):not([class*="content-velo-"]) { margin-top: var(--space-6); }

Umgesetzt in files/themes/velo/css/colors_and_type.css (Überschriften) und site.css (Content-Element-Abstand) im Contao-Projekt. .vw-prose-flow ist die Klasse für Kontexte ausserhalb eines .mod_article (z.B. innerhalb einer Card-Komponente), die denselben Rhythmus wollen.

Herausforderung willkommen: diese Seite ist der Ort für Anpassungen, nicht der Commit-Verlauf. Wirkt ein Wert in der Praxis falsch — zu eng, zu weit, falsche Ebene — hier ändern und den Grund dazuschreiben.

Prinzip Seitenanfang, Content-Elemente
Erstes Element der Seite

main.vw-main trägt bereits ein eigenes, responsives Top-Padding (--space-5/6/7 · 24/32/48px). Padding und Margin kollabieren nie über eine Elterngrenze hinweg — wenn eine Komponente zusätzlich ihr eigenes Top-Spacing für den Fall mitbringt, dass sie das erste Element der Seite ist, addiert sich das rein auf .vw-mains Padding drauf, nie "das Grössere gewinnt". Norm: das erste Element verlässt sich ausschliesslich auf .vw-main und trägt selbst nichts Zusätzliches bei — unabhängig davon, ob die Komponente ihr Top-Spacing sonst über padding-top oder margin-top löst.

/* Generisches Muster, zweimal unterschiedlich verdrahtet je nach Mechanismus:

   PADDING-Fall (der Wert sitzt auf dem inneren 
, nicht auf dem
   Contao-Wrapper-
 selbst -- :first-child auf dem WRAPPER zeigt mit einem
   Nachfahren-Selektor auf die Section):
*/
[class*="content-velo-"]:first-child .vw-section { padding-top: 0; }
.content-velo-hero:first-child     .vw-hero       { padding-top: 0; }
.content-velo-lead:first-child     .vw-page-intro { padding-top: 0; }
.content-velo-melde:first-child    .vw-melde      { padding-top: 0; }

/* MARGIN-Fall (margin-top sitzt meist direkt auf derselben Klasse, die schon
   der Contao-Wrapper ist, oder auf einer Section, die 1:1 dem Wrapper
   entspricht -- :first-child kombiniert direkt mit der eigenen Klasse): */
.content-velo-park-test:first-child .vw-parktest { margin-top: 0; }
.content-velo-gallery:first-child   .vw-gallery   { margin-top: 0; }
.content-velo-tabs:first-child                    { margin-top: 0; }
.content-velo-join:first-child      .vw-join      { margin-top: 0; }

Umgesetzt in files/themes/velo/css/site.css im Contao-Projekt, jede Regel direkt bei der betroffenen Komponente (nicht zentral an einer Stelle), mit Kommentar, warum genau dieser Mechanismus (Padding vs. Margin) für diese Komponente gilt. Bewusst keine einzelne globale Regel für alle Komponenten auf einmal -- .vw-join/ .vw-newsletter z.B. brauchen weiterhin ihre vollen 96px, wenn sie NICHT zuerst stehen (häufigster Fall), eine pauschale Regel hätte das nicht unterscheiden können, ohne :has()-Abfragen über jede Komponente zu bauen, die ihr eigenes Spacing schon löst.

Beim Erstbau einer Komponente immer mitdenken: trägt sie ein eigenes padding-top oder margin-top, das NICHT nur den Abstand zum vorangehenden Element regelt, sondern auch für den Fall "ich bin das erste Element der Seite" gedacht ist? Falls ja, gehört sofort eine :first-child-Zeile dazu, auch wenn die Komponente aktuell nirgends als erstes Element vorkommt — der Fehler zeigt sich sonst erst, sobald jemand die Komponenten-Reihenfolge auf einer echten Seite ändert.
